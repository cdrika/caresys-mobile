# Agency trial and billing integration

The authoritative implementation and contract are maintained in the backend [agency trial documentation](https://github.com/cdrika/caresys-backend/blob/main/Documentation/Agency_Free_Trial_and_Payments.md).

All endpoints below are relative to the configured HTTPS `/mobile/v1` base. Use `Authorization: Bearer ...`, omit cookies, and send a JSON object for mutations. No card details or Stripe secret keys are accepted from the mobile app.

| Endpoint | Purpose |
|---|---|
| `GET /me/agencies` | Agency selection with access flags |
| `GET /agencies/{ref}/billing` | Owner billing status/invoices or member lock notice |
| `GET /agencies/{ref}/billing/catalog` | Owner module labels, descriptions, dependencies and prices |
| `POST /agencies/{ref}/billing/invoices` | `{modules,service_level,worker_count,request_key}` |
| `GET /agencies/{ref}/billing/invoices/{invoice}/download` | Authenticated invoice PDF |
| `POST /agencies/{ref}/billing/checkout/setup` | `{request_key,confirm:"yes"}`; hosted Stripe card setup |
| `POST /agencies/{ref}/billing/checkout/payment` | `{request_key,confirm:"yes",invoice_ref}`; only after expiry |
| `POST /agencies/{ref}/billing/checkouts/{checkout}/complete` | `{}`; authoritative provider verification |

The app gets module prices from the backend catalog; local estimates are advisory and server-issued invoices are authoritative. Request keys use 32 hexadecimal characters generated by Expo Crypto. Retry a failed network operation using the same key; change keys after a successful operation or when selections change.

HTTP 402 means the agency is locked, not that the user's authentication token is invalid. Clear agency content and display owner billing or the generic member notice. HTTP 401 clears the credential and requests device pairing again. Refresh access on foregrounding, on selection, after checkout, and at least once per minute. The UI also evaluates known trial/paid expiry timestamps each second; the server enforces the deadline independently on every operation.

The backend may expose `legacy_active` for existing commercial agreements; those remain accessible. New agencies start `awaiting_card`, then `awaiting_modules`, `trial`, `payment_required` and `paid`. Trial duration is snapshotted by the backend. Module reselection does not restart the trial, and a paid invoice cannot be reused for another period.
